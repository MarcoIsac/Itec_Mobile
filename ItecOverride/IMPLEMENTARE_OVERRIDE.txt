ItecOverride - explicatii implementare (update curent)

1. Ce am adaugat acum
- In `index` exista buton nou pentru pagina de stickere salvate (`My Stickers`).
- Am adaugat ecran nou `app/stickers.tsx` unde vezi toate stickerele generate si salvate local din `generator`.
- In `drawScreen` ai selector de sursa pentru sticker:
  - `Din galerie`
  - stickerele salvate local din generator (cu refresh local)
- Stickerul ales din lista locala este incarcat in draft si transformat in base64 pentru submit (ramane compatibil cu sync-ul server).
- Serverul de sincronizare foloseste MongoDB (daca exista `MONGODB_URI`) si are fallback automat pe JSON local daca MongoDB nu este disponibil.

2. Fisiere importante
- `app/index.tsx` - buton nou catre galeria locala de stickere.
- `app/stickers.tsx` - pagina noua pentru vizualizarea stickerelor generate.
- `app/generator.tsx` - salvare sticker prin util comun.
- `app/drawScreen.tsx` - selectie sticker din galerie sau din local generator.
- `app/lib/sticker-storage.ts` - util comun AsyncStorage pentru stickerele generate.
- `app/lib/ar-store.ts` - persistenta locala + sync la server pentru postere.
- `server/server.js` - API sync cu storage MongoDB + fallback local.

3. Config pentru colaborare intre toti utilizatorii
- Backend:
  - seteaza `MONGODB_URI` catre clusterul MongoDB (Atlas sau self-hosted)
  - optional: `MONGODB_DB_NAME` (default `override`)
  - optional: `MONGODB_COLLECTION` (default `posters`)
  - ruleaza serverul: `npm run server`
- Aplicatie:
  - seteaza `EXPO_PUBLIC_OVERRIDE_SERVER_URL` catre URL-ul public al backend-ului (ex: `https://override-api.example.com`)
  - foloseste aceeasi valoare pentru toate build-urile/dispozitivele

4. Export/build recomandat
- Pentru AR real pe Android: `npx expo run:android` (development build) sau build release prin EAS.
- Pentru release catre utilizatori, seteaza in pipeline-ul de build variabila `EXPO_PUBLIC_OVERRIDE_SERVER_URL` catre backend-ul public.
- Daca backend-ul nu este public / nu are MongoDB accesibil, utilizatorii vor vedea doar date locale pe dispozitivul lor.

5. Verificare facuta dupa modificari
- `npx tsc --noEmit` -> OK
- `npm run lint` -> OK
